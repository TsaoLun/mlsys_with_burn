# 2026-09-14 对齐 Burn 0.22.0-pre.3 / CubeCL Pliron

## 目标

用户要求结合 Burn 0.22.0 Pre-Release 3，特别是官方说明
「CubeCL has migrated to Pliron, laying the foundation for the next
generation of its compiler infrastructure.」，对全书内容重修。

## 选择

- 第二写作周期基线改为 tag `v0.22.0-pre.3` / CubeCL `v0.11.0-pre.3` /
  CubeK `v0.3.0-pre.3` / burn-onnx `v0.22.0-pre.3`（D027）。
- 读者主路径讲 Pliron 作为 Kernel 编译器地基；Fusion IR 与 autodiff
  tape 明确未迁。
- 发布 tag 的 Burn/onnx manifest 用 crates.io 钉版本；教材对 CubeCL
  直连示例仍用 GitHub SHA。禁止 `path` / `[patch]`。
- ONNX 版本对齐后仍不进入根 workspace：隔离理由从「两个 Burn git SHA」
  改为独立产品与未跑通 fixture。

## 核验过的源码事实

- `KernelDefinition` 仍在 `cubecl-runtime`：`body: Scope`、`info`、
  `settings`。Scope 内部是 Pliron `Context` + `ModuleOp`。
- 方言在 `cubecl-ir/src/dialect/`（math、memory、scf、vector、plane、
  matrix 等）。
- `cubecl-opt` 是自定义 Pliron Pass（mem2reg、sroa、simple_cse 等），
  不再是独立 petgraph CFG Optimizer。
- `CpuRuntime` 的 `CpuCompiler = PlironCompiler`（`cubecl-llvm`）。
- `burn-cpu` 包装 `CubeBackend<CpuRuntime>`；crate 描述仍写
  “MLIR based”，以 Compiler 源码为准。
- `DispatchDevice` 含 Capture；`burn-ir::GraphIr` 有显式 inputs/outputs。
- `burn-ndarray` `deprecated since 0.22.0`；`burn-candle` 已删除。
- `TensorData` 仍是 `{ bytes, shape, dtype }`，反序列化校验字节长度。
- burn-onnx 发布 manifest：`burn = "=0.22.0-pre.3"`。开发注释里的
  git rev `a467575...` 不是 tag 真相。
- `tracel-llvm-bundler = 22.1.4-6`；release 仍无 macos-x64 资产。
