## `burn-rl` 核心抽象

固定 `burn/crates/burn-rl` revision 核验：

### Environment

`Environment` 定义：

- `State`：环境内部状态类型；
- `Action`：环境接受的动作类型；
- `MAX_STEPS`：单 episode 最大步数常量；
- `state()`：读取当前状态；
- `step(action)`：返回 `StepResult`；
- `reset()`：恢复初始状态。

`StepResult` 同时包含 `next_state`、浮点 `reward`、`done` 和 `truncated`。
这两个结束标志必须区分：`done` 表示环境自身达到终止条件，
`truncated` 表示达到时间/长度上限。Burn 的训练 runner 在写入 transition
的 `done` tensor 时把二者合并，但 `TimeStep` 自己仍保存 `done` 字段和
episode 统计。

`EnvironmentInit` 是可 clone 的环境构造器；函数 `Fn() -> E` 可以直接
实现它。这使单线程环境和多环境 runner 都可以按需创建自己的实例，而不是
在线程之间共享一个可变环境。

### Policy、Batchable 与转换边界

`Policy` 不是具体算法。它要求调用者实现：

- `forward(observation batch)` 产生 action distribution；
- `action(observation batch, deterministic)` 产生 action 和 per-action
  context；
- `update(policy state)` 更新当前策略；
- `state`、`load_record` 和 `to_device`。

`Batchable` 负责把多个 observation/action/distribution 合并和拆分；
`ToObservation`/`ToAction` 负责在 environment state/action 与 policy
tensor 或其他 representation 之间转换。Rust 关联类型把这些边界写在
trait 实现中，编译器可以检查 policy 和 environment 是否匹配。

`PolicyState::Record` 只由具体 policy 决定。它可以是 `ModuleRecord`，也
可以是用户自定义状态；`burn-rl` 不强制一种神经网络结构或 checkpoint
格式。

### TransitionBuffer

`TransitionBuffer<SB, AB>` 是 tensor-backed circular buffer：

- 首次 `push` 时根据 state/action 的 `SliceAccess` 形状惰性分配；
- 连续保存 states、next_states、actions、rewards 和 dones；
- 超过 capacity 时覆盖最旧 transition；
- `sample(batch_size)` 生成随机 index 并沿第 0 维选择 batch；
- `SliceAccess` 需要实现 `zeros_like`、`select` 和
  `slice_assign_inplace`。

固定实现对 `Tensor<2>` 提供了 `SliceAccess`。`sample` 在 batch 大于当前
长度时 panic，capacity 为零也不是有效配置；教学实验在调用前显式校验
这些条件。它提供 replay storage，不自动实现 prioritized replay、n-step
return、trajectory padding 或分布式一致性。

### AsyncPolicy

`AsyncPolicy` 在 native std 线程中以 mpsc channel 接收 action/forward/
update/device 请求，由 `PolicyInferenceServer` 按 `autobatch_size` 和
活跃 agent 数收集请求。它支持多个环境把 observation 合批后进行一次
policy inference，但：

- 需要所有 observation/action/distribution 满足 `Batchable`；
- 请求会等待 flush 条件，batch size 和活跃 agent 数影响延迟；
- `load_record` 明确未实现，要求先在 inner policy 上加载；
- 这是进程内 inference batching，不是跨节点 actor scheduler。

## `burn-train` RL 编排

固定 `burn-train` 的 `learner/rl/` 核验：

- `RLComponentsTypes` 用关联类型连接 Env、State、Action、Policy、
  PolicyLearner、PolicyState 和 training output；
- `AgentEnvBaseLoop` 顺序执行 environment step，构造 `TimeStep` 和
  `Transition`，维护 episode length/cumulative reward；
- `AgentEnvAsyncLoop` 把环境放进线程，通过 channel 提供 step/episode
  请求；
- `MultiAgentEnvLoop` 创建多个环境线程，并使用 `AsyncPolicy` 做 inference
  batching；
- `OffPolicyConfig` 配置环境数、autobatch、replay capacity、收集间隔、
  train steps、evaluation interval、batch size 和 warmup；
- `OffPolicyStrategy` 按 collect→push→sample→`PolicyLearner::train`
  →可选 evaluation/checkpoint 顺序运行；
- `RLTraining` 负责 metrics、event processor、checkpoint、inference
  device 和 launch；
- `RLCheckpointer` 分别保存 policy record 和 learning-agent record。

`burn-train` 的 `PolicyLearner` 仍需要用户实现具体 loss、optimizer step、
target network、探索策略和 learner record。它不内置通用 DQN、PPO、SAC 或
MARL 算法。

固定 `burn/examples/dqn-agent` 展示了一个完整 DQN 对照：

- gym CartPole 通过 wrapper 实现 `Environment`；
- `DQN` 实现 `Policy`；
- `DqnLearningAgent` 自己计算 TD target、MSE、autodiff backward、
  optimizer step 和 target soft update；
- `DqnLearningRecord` 自定义打包 policy model、target model 和 optimizer
  record；
- `RLTraining::OffPolicyStrategy` 负责 rollout/replay/evaluation/checkpoint。

该 example 是独立 workspace，依赖 gym-rs 和 native SDL2 生态，不能作为根
项目默认 CPU CI 实验。

## 能力与限制清单

| 结论 | 证据级别 |
|---|---|
| 可定义有 `done`/`truncated` 的 Rust 环境并生成 typed step result | 固定 `burn-rl` 源码 |
| 可将 state/action 映射为 policy 表示并实现批处理 | 固定 `burn-rl` traits |
| 可在单进程中做 bounded circular replay 和随机 batch sampling | 固定源码 + 本章 CPU 实验 |
| `burn-train` 有多环境 async rollout 与 off-policy 编排入口 | 固定 `burn-train` 源码 |
| Burn `rl` 自动提供 DQN/PPO/SAC 或通用算法 | **不成立**；具体 learner 由用户实现 |
| 当前固定快照提供通用分布式 actor/learner、league 或 MARL runtime | **未核验/不承诺** |
| TransitionBuffer 提供 prioritized replay、n-step、跨进程一致性 | **不成立**；当前实现没有这些协议 |

## 实验规划

新增 `examples/ch08-rl-rollout`，使用固定主线 Burn 的 Flex CPU：

```text
deterministic CounterEnv
   → Environment::step
   → Tensor state/action encoding
   → TransitionBuffer circular storage
   → random replay batch
   → scalar tabular TD update
```

测试断言：

1. episode 在 `done` 或 `truncated` 边界重置；
2. rollout 产生预期 transition 数，buffer 长度受 capacity 限制；
3. replay batch 的 state/action/reward/done shapes 正确；
4. 一个确定性 Q-learning 更新把已观测动作的 Q 值向 TD target 推进；
5. zero capacity、zero steps 和过大 sample batch 返回描述性错误。

实验不实现神经网络 policy、完整 DQN 或多智能体通信；表格 TD update
用于隔离 RL 的 credit/bootstrapping 数学，让 Burn 的环境和 replay
边界可以在无外部 simulator 的 CPU 上被测试。
