## 能力与限制清单

| 结论 | 证据级别 |
|---|---|
| Burn 有单设备、多设备和 DDP 训练策略入口 | 固定 `burn-train` 源码 |
| Burn 有 `DistributedContext`、`CollectiveTensor` 和 `all_reduce` 抽象 | 固定 `burn-tensor`/backend 源码 |
| CubeCL 有本地 ComputeClient、stream、memory 和 CUDA collective 入口 | 固定 CubeCL/Burn 源码 |
| Flex CPU 可以作为本章 collective 运行验证 backend | **不成立**；固定源码明确不支持 collective |
| Burn 固定快照提供集群作业队列、配额、拓扑放置和多租户隔离 | **不成立**；需要外部控制面 |
| Burn 固定快照提供 rank/world rendezvous、elastic membership、自动重试 | **未核验/不承诺** |
| Burn checkpoint 接口提供跨节点原子提交和故障恢复 | **不成立**；它保存训练状态，不是集群一致性协议 |
| CubeCL stream scheduler 等价于集群 GPU 调度器 | **不成立**；它只管理设备运行时内的任务 |

## 实验规划

新增 `examples/ch09-cluster-simulator`，只用 Rust 标准库：

```text
logical cluster (GPU/node/rack/memory)
    → FIFO or topology-aware placement
    → gang admission
    → alpha/beta collective cost
    → deterministic failure
    → checkpoint replay and retry
    → queue/makespan/traffic/observability report
```

测试断言：

1. GPU 资源不会为负，失败或完成后资源全部归还；
2. gang scheduling 不会部分启动作业；
3. 相同输入产生相同 trace 和指标；
4. fixture 中 topology-aware placement 减少跨机柜 bytes；
5. gradient bytes 增加时通信成本单调增加；
6. 失败从最近 checkpoint 恢复，记录 replay steps 和 retry；
7. `p95_queue_wait` 可从确定性 job report 计算。

实验不启动真实线程、不调用 `sleep`、不连接网络、不依赖 Burn/CUDA/NCCL，
不把虚拟时间或跨机柜 penalty 当成硬件 benchmark。

## Crosswalk 与证据状态

逐文件对照见 [`../comparison/openmlsys-v1-crosswalk.md`](../comparison/openmlsys-v1-crosswalk.md)
的“分布式训练”段；第 6 章是训练/通信数据面，本章是集群控制面。
队列、gang admission、拓扑放置、`alpha + beta * bytes`、checkpoint
replay 和 telemetry trace 属于 `源码核验 + CPU 可运行验证/协议模型`；
真实 GPU/NCCL、网络拥塞、弹性成员和多租户 runtime 属于
`可选平台实验/明确未覆盖`。

P1 扩展 `TraceEvent` 为版本化 `TraceRecord`，包含 event、job/attempt、
虚拟时间、placement、checkpoint 和 replay 字段；队列等待、公平和链路
热点仍只在 CPU 模拟结果与协议模型层解释，不外推为集群 benchmark。
