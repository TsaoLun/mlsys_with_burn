## Burn IR 与 Fusion 事实来源

| 结论 | 固定源码 |
|---|---|
| OperationIr、TensorIr、TensorId 与 TensorStatus 描述延迟操作和资源状态 | `burn/crates/burn-ir/src/operation.rs`、`tensor.rs` |
| Fusion Tensor op 注册 OperationIr，而不是立即执行底层算子 | `burn/crates/burn-fusion/src/ops/` |
| GlobalFusionClient 将操作注册到按 stream 管理的 FusionServer | `burn/crates/burn-fusion/src/client.rs`、`server.rs` |
| MultiStream/OperationQueue 搜索并执行优化块或 unfused 操作 | `burn/crates/burn-fusion/src/stream/`、`search/` |
| CubeCL Backend 注册 ElementWise、Matmul、Reduce 等 fuser | `burn/crates/burn-cubecl/src/fusion.rs`、`burn-cubecl-fusion/src/optim/` |
| 读回和 `Device::sync` 会 drain 对应 stream，形成物化边界 | `burn/crates/burn-fusion/src/server.rs`、`client.rs` |
| Flex 直接执行，不产生 Fusion OperationIr | `burn/crates/burn-flex/ARCHITECTURE.md`、`burn/crates/burn-flex/src/` |
| FusionInspector 是 `test-util` 下的测试观测 API，不是生产接口 | `burn/crates/burn-fusion/src/inspect.rs` |
| add→exp 融合与同步切分的上游回归模式 | `burn/crates/burn-backend-tests/tests/fusion/fusion_shape.rs` |

## CubeCL 编译与 Runtime 事实来源

| 结论 | 固定源码 |
|---|---|
| `#[cube]` 宏生成 expand，向 `cubecl_ir::Scope` 注册指令 | `cubecl/crates/cubecl-macros/src/generate/` |
| KernelBuilder 将 Scope 与 IO/设置集成为 KernelDefinition | `cubecl/crates/cubecl-core/src/compute/`、`cubecl/crates/cubecl-runtime/src/kernel.rs` |
| 不同 Compiler 使用不同优化/Lowering 管线 | `cubecl/crates/cubecl-spirv/src/compiler.rs`、`cubecl/crates/cubecl-cpp/src/`、`cubecl/crates/cubecl-cpu/src/` |
| CubeCL 当前以 JIT 和编译缓存为主，没有统一一等 AOT API | `cubecl/README.md`、`cubecl/crates/cubecl-runtime/src/compiler.rs` |
| ComputeClient launch 入队，read/sync/flush 构成等待边界 | `cubecl/crates/cubecl-runtime/src/client.rs` |
| Runtime 含 sliced/exclusive/persistent 等内存池 | `cubecl/crates/cubecl-runtime/src/memory_management/` |
