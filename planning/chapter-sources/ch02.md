## Burn 事实来源

| 结论 | 固定源码 |
|---|---|
| 公共张量为 `Tensor<const D, K>` | `burn/crates/burn-tensor/src/tensor/api/base.rs` |
| shape 与 dtype/device 主要是运行时属性 | `burn-tensor` 的 `base.rs`、`options.rs`、`device.rs` |
| 运行时后端由 `Device`/`DispatchDevice` 选择 | `burn/crates/burn-dispatch/src/device.rs` |
| 用户 Module 与 Record 不再携带 Backend 泛型 | `burn/crates/burn-core/src/module/`、`src/store/mod.rs` |
| 自动微分是一阶反模式动态图 | `burn/crates/burn-autodiff/README.md`、`src/runtime/` |
| `require_grad`、`backward`、`grad` 是当前用户 API | `burn-tensor/src/tensor/api/float.rs`、`autodiff.rs` |
| autodiff tape 不等于 burn-ir/Fusion 图 | `burn-autodiff`、`burn-ir`、`burn-fusion` 三个 crate |

## 能力边界

- 旧 Burn Book 中大量 `Tensor<B, D>` 示例不适用于该快照。
- 当前公开用户 API 通过 Device 运行时分派，Backend trait 主要面向实现层。
- Burn 自动微分只支持一阶反模式；不能把双重 `.autodiff()` 写成高阶导。
- Flex 使用 eager 执行和 autodiff tape，不经过 CubeCL Fusion。
- `detach()`、Tensor `inner()` 与 Device `inner()` 含义不同。
- `ModuleRecord` 是当前状态载体，不使用旧式 `Record<B>`。
