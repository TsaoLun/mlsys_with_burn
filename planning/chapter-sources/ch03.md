## CubeCL 事实来源

| 结论 | 固定源码 |
|---|---|
| `#[cube]` 将 Rust 风格函数展开为 CubeCL IR | `cubecl/crates/cubecl-macros/`、`cubecl/crates/cubecl-core/` |
| `CubeCount`/`CubeDim` 定义 grid 与 cube 内 unit | `cubecl/crates/cubecl-runtime/src/server/base.rs`、`cubecl/crates/cubecl-core/src/frontend/topology.rs` |
| `ABSOLUTE_POS` 是全局线性 unit 索引 | `cubecl/crates/cubecl-core/src/frontend/topology.rs` |
| Runtime/ComputeClient 管理编译、buffer 与 launch | `cubecl/crates/cubecl-runtime/src/runtime.rs`、`cubecl/crates/cubecl-runtime/src/client.rs` |
| CPU runtime 可运行 CubeCL Kernel | `cubecl/crates/cubecl-cpu/`、`cubecl/examples/gelu/` |
| 当前向量类型名是 `Vector<F, N>`，不是旧 `Line` | `cubecl/cubecl-book/src/core-features/vectorization.md` |
| raw BufferArg 长度和 unchecked launch 构成 unsafe 边界 | `cubecl/crates/cubecl-core/src/frontend/container/slice/launch.rs` |

## CubeK 与 Burn 集成

| 结论 | 固定源码 |
|---|---|
| CubeK Guide 定义 Blueprint–Routine 架构与 Autotuner；具体 crate 另有 Strategy/Launch 接口 | `cubek/GUIDE.md`、`cubek/crates/cubek-matmul/src/` |
| matmul 包含 Naive、CpuGemm、CMMA/MMA/TMA 等策略族 | `cubek/crates/cubek-matmul/src/strategy/`、`cubek/crates/cubek-matmul/src/routines/` |
| Burn matmul 经 `cubek::matmul::launch::launch_ref` | `burn/crates/burn-cubecl/src/kernel/matmul/base.rs` |
| Conv、reduce、attention、pool、FFT、random 等部分路径使用 CubeK | `burn/crates/burn-cubecl/src/kernel/` |
| 仍有大量纯 CubeCL Kernel 和 fallback，不是所有 Burn op 都经过 CubeK | `burn/crates/burn-cubecl/src/kernel/`、`burn/crates/burn-cubecl/src/ops/` |
| 策略会按设备能力过滤并由 LocalTuner 测量 | `burn/crates/burn-cubecl/src/kernel/*/tune.rs` |

## 本章不作出的承诺

- 不声称 CPU 实验能代表 GPU 性能。
- 不声称所有 CubeCL 后端支持 Plane、CMMA、TMA 或相同 dtype。
- 不声称所有 Burn 算子或卷积路径都使用 CubeK。
- 不声称 CubeK FlashAttention backward 已被 Burn 集成。
- 不把某次 autotune 结果描述为跨设备稳定结论。
- 不复述 OpenMLSys 在特定 RTX 3080/CUDA 版本上的性能胜负。

## Crosswalk 与证据状态

逐文件对照见 [`../comparison/openmlsys-v1-crosswalk.md`](../comparison/openmlsys-v1-crosswalk.md)
的“加速器”段。CubeCL Kernel 正确性、tile load/intensity 模型属于
`源码核验 + CPU 可运行验证/协议模型`；真实 GPU GEMM、shared-memory
和设备性能比较属于 `可选平台实验`，不能由默认 CPU CI 代替。

对应比较卡位于 `book/src/comparison-cards.md` 的“GEMM 与加速器”，固定
测量协议要求显式记录 shape、dtype、backend、warm-up、sync 和 reference。
