## Burn 技术栈证据

| 结论 | 固定源码 |
|---|---|
| `Tensor` 在 0.22 中是 `Tensor<D, K>`，不再携带 Backend 类型参数 | `burn/crates/burn-tensor/src/tensor/api/base.rs` |
| 后端能力绑定在 `Device`，并由 `DispatchDevice` 选择 | `burn/crates/burn-tensor/src/device.rs`、`burn/crates/burn-dispatch/src/device.rs` |
| 后端实现共享 `Backend` / `BackendTypes` 契约 | `burn/crates/burn-backend/src/backend/base.rs` |
| 教材默认 CPU 后端是 Flex | `burn/crates/burn-flex/src/backend.rs` |
| CubeCL 提供设备无关 Kernel 编译和运行时 | `cubecl/README.md`、`cubecl/crates/` |
| CubeK 提供矩阵乘、归约、注意力等高性能算子 | `cubek/README.md`、`cubek/crates/` |
| ONNX 导入是独立仓库，且拥有自己的 Burn revision | `burn-onnx/Cargo.toml`、`burn-onnx/SUPPORTED-ONNX-OPS.md` |

## 第一版不作出的承诺

- 不声称 Burn Book 中所有旧泛型示例都与 0.22 API 一致。
- 不声称所有后端都支持相同的数据类型、融合、量化或图捕获能力。
- 不声称 burn-onnx 支持全部 ONNX 算子或与教材 Burn commit 完全同步。
- 不将 Remote（当前为 Beta）、QAT 或完整大规模分布式训练描述为成熟能力。
- 不把 CubeK 描述为模型开发者通常直接调用的高层框架。
