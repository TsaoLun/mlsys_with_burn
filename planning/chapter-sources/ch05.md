## Burn 数据集与 DataLoader 事实

| 结论 | 固定源码 |
|---|---|
| `Dataset<I, E>` 要求 `Send + Sync`，提供 `get`、`get_many`、`len`、`iter`；越界是 panic，真实读取错误通过 `Result` 返回 | `burn/crates/burn-dataset/src/dataset/base.rs` |
| 默认 `DatasetIterator` 按索引顺序逐项调用 `get` | `burn/crates/burn-dataset/src/dataset/iterator.rs` |
| `InMemDataset` 保存 `Vec<I>`；CSV/JSON 构造函数把数据加载到内存 | `burn/crates/burn-dataset/src/dataset/in_memory.rs` |
| `DatasetError` 类型擦除线程安全错误 | `burn/crates/burn-dataset/src/dataset/error.rs` |
| `MapperDataset` 对 item 做惰性 map | `burn/crates/burn-dataset/src/transform/mapper.rs` |
| `SelectionDataset` 保存索引，支持乱序、重复、slice 和 split | `burn/crates/burn-dataset/src/transform/selection.rs` |
| `ShuffledDataset` 是对全量索引随机排列的 wrapper | `burn/crates/burn-dataset/src/transform/shuffle.rs` |
| `SamplerDataset` 区分 with/without replacement，并支持固定大小/比例 | `burn/crates/burn-dataset/src/transform/sampler.rs`、`options.rs` |
| `PartialDataset::split_chunks` 按完整 batch chunk 切分，最后分片保留余数 | `burn/crates/burn-dataset/src/transform/partial.rs` |
| SQLite Dataset 用 split、`row_id` 和连接池按索引读取；`get_many` 保持请求顺序与重复 | `burn/crates/burn-dataset/src/dataset/sqlite.rs` |
| `Batcher<I,O>` 在 `Device` 上把 items 组成输出 | `burn/crates/burn-core/src/data/dataloader/batcher.rs` |
| `DataLoader<O>` 提供 iterator、item 数、to_device 和 slice；iterator 返回 progress | `burn/crates/burn-core/src/data/dataloader/base.rs` |
| builder 配置 batch size、seed、worker 数和 device；0/None 与 >0 选择不同 loader | `burn/crates/burn-core/src/data/dataloader/builder.rs` |
| `FixBatchStrategy` 会在迭代末尾发出不完整 batch | `burn/crates/burn-core/src/data/dataloader/strategy.rs`、`batch.rs` 测试 |
| 单线程 `BatchDataLoader` 在每个 iterator 创建时按 RNG 生成 shuffled wrapper | `burn/crates/burn-core/src/data/dataloader/batch.rs` |
| 多线程 loader 预 shuffle/切分 Dataset，后台 worker 通过 bounded mpsc 发送 Batch/Done/Error | `burn/crates/burn-core/src/data/dataloader/multithread.rs` |
| 多线程 iterator 按 receiver 到达顺序返回，没有全局序号重排 | `burn/crates/burn-core/src/data/dataloader/multithread.rs` 的 Message 与 iterator |
| 多设备切分按连续范围并把最后余数给最后设备 | `burn/crates/burn-core/src/data/dataloader/split.rs` |

## Burn 功能与 feature 边界

`burn/crates/burn/Cargo.toml` 把 `dataset` 映射到
`burn-core/dataset`；`burn-core` 再公开 `burn_dataset` 的 Dataset 与
`dataloader` 模块。`burn-dataset/Cargo.toml` 将 SQLite、vision、audio、
NLP、network 等功能拆为 feature；本章实验只通过根项目的固定 Burn Git
依赖启用 `dataset`，没有使用本地 path 或 `[patch]`。

## 本章不作出的承诺

- 不声称 `burn-dataset` 的一般 `Mapper` 会自动进入 Burn Fusion 或 CubeCL；
- 不声称 `num_workers > 0` 保证全局 batch 到达顺序；
- 不把一次 CPU 内存数据测量外推为文件、GPU 或分布式吞吐结论；
- 不把 `split_dataloader` 描述为跨节点分布式 sampler 或通信协议；
- 不把固定 seed 描述为跨版本、跨后端和跨线程调度的绝对复现保证；
- 不声称固定快照拥有通用 prefetch、pinned memory、zero-copy 或异构
  Dataset map API；
- 不把 OpenMLSys 的 MindRecord、MindData Connector、Ascend/DALI/Ray
  实现细节冒充 Burn 已验证能力。

## 2026-08-08 深度加厚记录

- `01`：为 F/P/G 背压模型补队列消化演算——长期缺口下 $Q$ 只延迟空转
  $Q/(G-F)$ 秒；偶发抖动下按累计缺口选容量（200 batch 抖动用
  $Q=256$ 吸收）。
- `03`：补不完整 batch 计数演算（1000 样本、batch 32 → 31 完整 +
  1 个 8 样本尾批，$1000 = 31 \times 32 + 8$）。
- `04`：补 shuffle 索引内存演算（$10^6$ 样本 → 8 MiB 索引表 vs 复制
  样本约 1 GiB），说明索引重排把开销与样本大小解耦。
