# 机器学习系统的设计目标

一个机器学习系统通常需要同时覆盖六类能力。它们不是用于给产品打分的
清单，而是帮助我们定位系统边界的坐标。

## 神经网络编程

系统要让开发者组合线性层、卷积、注意力和自定义算子，并管理模型参数、
设备和数据类型。高层接口应便于表达模型，底层又必须保留扩展和性能优化的
入口。

Rust 技术栈特别强调这些抽象的类型边界：模型模块可以由 trait 和 derive
宏组织，张量秩及元素类别能进入类型系统，而实际设备和部分 dtype 选择又
可以保留到运行时。第 2 章将讨论这种静态与动态信息的分工。

## 自动微分

训练需要计算损失相对于参数的梯度。自动微分（automatic
differentiation）根据程序执行的基本运算应用链式法则，避免用户手工推导
大型模型的导数。

自动微分不只是数学工具，它还涉及保存哪些中间值、何时释放或重算、如何
处理控制流，以及梯度计算是否能在不同后端上复用。Burn 将自动微分作为
可组合的设备能力；具体实现留到第 2 章。

## 数据管理与处理

系统需要读取、解析、打乱、批处理和增强训练数据，并管理验证集、测试集和
模型状态。数据管道必须与设备计算并行，才能减少加速器等待。

Rust 的迭代器、线程安全类型和显式错误处理为数据管道提供了不同于动态语言
的组合方式。第 5 章会进一步讨论 Burn Dataset 与自定义流水线。

## 训练与部署

训练系统组织前向计算、反向传播、优化器、指标和检查点；部署系统则需要
恢复权重、选择推理后端、处理请求并监控结果。二者共享模型语义，但优化
目标往往不同。

Burn 的一个重要方向是让训练和推理复用 Rust 模型代码，再通过 Device、
Record 和 feature 组合能力。外部模型则可通过 burn-onnx 在构建时转换成
Rust 代码和权重。这个方向不等于“任意 ONNX 模型都能无损导入”，具体算子
覆盖必须以固定版本的支持表为准。

## 硬件加速

矩阵乘、卷积和注意力等操作适合大规模并行硬件。系统需要选择 Kernel、
管理设备内存、安排异步执行，并针对数据类型、形状和硬件能力进行优化。

本书通过 CubeCL 讲解设备无关 Kernel 和编译运行时，通过 CubeK 研究高性能
算子实现。Flex CPU 后端并不经过 CubeCL/CubeK；后端之间共享的是张量语义
和调度接口，而不是完全相同的内部执行路径。

## 分布式执行

当数据、模型或吞吐需求超过单机能力时，系统需要跨进程和节点分配工作。
这里涉及集合通信、参数同步、拓扑、故障恢复和调度。

框架提供多设备接口只是起点。网络、集群编排和容错通常位于框架之外。
因此第 6 章会区分 Burn 当前可验证的训练能力与通用并行原理，第 9 章则把
GPU 集群作为独立基础设施研究。

## 为什么不能用一种现有系统替代全部能力

神经网络库可能擅长算子和自动微分，却缺少大规模数据、部署和集群能力；
通用数据处理系统可能拥有成熟的容错和分布式执行，却不了解张量、梯度和
加速器。现代机器学习平台通常是多个系统的组合，而不是一个无边界的框架。

| 系统层次 | 主要优势 | 通常需要外部系统补充 |
|---|---|---|
| 张量/神经网络库 | 模型、算子、自动微分 | 数据平台、服务、集群治理 |
| 通用数据系统 | 存储、批流处理、容错 | 张量语义、梯度、设备 Kernel |
| 机器学习框架 | 模型到设备的主要执行路径 | 调度、观测、产品数据与服务治理 |

本书把 Burn 视作贯穿主要执行路径的案例，而不是声称它应当独自实现表中
所有外部能力。
