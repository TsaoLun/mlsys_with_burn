# 机器学习应用与系统负载

机器学习从数据中归纳规律。按反馈信号粗略划分，常见任务包括：

- **监督学习（supervised learning）**：样本带有目标值，例如图像分类、
  语音识别和回归预测；
- **无监督学习（unsupervised learning）**：没有直接标签，系统需要发现
  数据结构，例如聚类、表示学习和生成建模；
- **强化学习（reinforcement learning）**：智能体与环境交互，根据延迟
  奖励改进策略。

这种算法分类很重要，但对系统设计还不够。两个都叫“监督学习”的任务，
可能分别是单机上的小型表格模型和跨越数千张 GPU 的生成模型。系统更关心
负载会消耗什么资源、何时产生数据、必须满足怎样的时延和正确性要求。

## 从应用名称转向负载特征

分析一个机器学习应用时，可以先问四组问题。

### 计算

- 主要操作是矩阵乘、卷积、归约，还是不规则索引？
- 张量形状在编译前是否已知，是否频繁变化？
- 使用 F32、F16、BF16、整数还是量化数据？
- 计算受算力限制，还是受内存带宽限制？

大多数现代神经网络以张量运算为主体，这使通用加速器和算子库成为可能；
但稀疏访问、分词、采样和环境模拟等非规则工作仍可能在 CPU 上占据主导。

### 数据

- 数据来自本地文件、对象存储、数据库，还是在线环境？
- 样本能否随机读取，是否需要清洗、增强和缓存？
- 一个批次的准备时间能否隐藏在设备计算之后？
- 多个训练进程如何避免重复或遗漏样本？

当加速器每秒可以执行大量计算时，慢速解码或网络读取会让昂贵设备空闲。
因此数据处理不是训练脚本之前的一次准备，而是持续运行的系统流水线。

### 硬件

- 模型和中间结果是否能放入一台设备的内存？
- 目标设备是 CPU、独立 GPU、浏览器中的 WebGPU，还是嵌入式平台？
- 不同设备是否支持相同的数据类型和算子？
- 主机与设备、设备与设备之间的数据移动成本是多少？

同一个数学表达式在不同硬件上可能需要不同 Kernel、内存布局和调度策略。
“能执行”与“高效执行”是两项不同要求。

### 生命周期

- 当前阶段是训练、离线推理还是在线服务？
- 训练状态如何保存和恢复？
- 推理请求更重视吞吐、尾延迟、成本还是能耗？
- 模型如何从其他生态导入，又如何验证转换前后的语义一致？

训练通常允许批量吞吐和长时间执行，在线推理则可能要求毫秒级尾延迟。
生成式模型又引入了可变序列、状态缓存和逐步解码；多模态模型还需要协调
文本、图像或音频的不同预处理与张量形状。生命周期差异会改变批处理、
内存、编译和部署的设计选择。

## 为什么以神经网络为主线

支持向量机、逻辑回归和树模型同样属于机器学习。考虑到现代系统的大部分
复杂性集中在张量程序、自动微分、异构加速和大规模训练，本书以神经网络
作为主要案例。这里的目标不是教授具体模型结构，而是利用其负载覆盖：

- 规则而密集的张量计算；
- 动态构建的训练过程与梯度；
- 大规模数据流水线；
- 单设备到多设备的扩展；
- 从训练权重到多平台推理的完整生命周期。

后续章节会不断回到本节的四个维度。任何优化都应先说明它改变了哪种资源
约束，而不是仅报告某个 API “更快”。
