# 第 1 章 导论

训练一个模型时，我们看到数据、张量、损失和优化器；把同一件事放进真实
系统，还会碰到设备、编译、内存、通信、存储、排队和故障。机器学习系统
（machine learning systems）研究的正是这些写在公式外面、却决定任务能否
按时、按预算跑完的问题。

本章先建立一张地图：负载怎么拆、系统要满足哪些目标、从编程接口到硬件
有哪些层。Burn 是后面各章打开源码时的贯穿案例，不是这张地图的边界。
全书章节与产业名字的对照见[从应用到集群](infra-map.md)。

## 本章问题

一次机器学习任务如何从「模型定义」变成跨设备的训练、服务和调度？各层
分别承担什么？读者又该按什么顺序往下走？

## 学习目标

完成本章后，你应该能够：

1. 从计算、数据、硬件和运行生命周期四个角度描述机器学习负载；
2. 解释现代机器学习系统共同面对的设计目标；
3. 画出从用户接口、张量执行、IR、Kernel 到设备运行时的分层路径；
4. 说出 Burn、CubeCL、CubeK 与 burn-onnx 各自负责哪一段；
5. 理解 `Tensor`、`Device` 和运行时分派的基本关系；
6. 选一条适合自己的阅读路径（模型、基础设施，或 Kernel）。

## 先修知识

掌握 Rust 基本语法和常见机器学习术语即可。尚未接触自动微分、GPU 或
分布式系统没有关系：本章只建立地图。

## 本章路线

先把应用写成可分析的负载，再从设计目标得到分层架构，然后把架构映射到
Burn 技术栈，最后用一个小实验走通 Device → Backend → Tensor。
