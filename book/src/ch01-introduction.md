# 第 1 章 导论

训练一个模型时，我们会看到数据、张量、损失函数和优化器；把模型放进真实
系统后，还会遇到设备、编译、内存、通信、存储、服务和故障。机器学习系统
（machine learning systems）研究的正是这些算法公式之外、又决定模型能否
高效可靠运行的问题。

本书以 Burn 为贯穿案例，但不会把“学习一个框架的 API”当作最终目标。
我们将反复在三个层次之间移动：

```text
框架无关的系统原理
        ↓
Burn 的张量、训练与部署抽象
        ↓
Burn IR / Fusion → burn-cubecl
                    ├→ 通用 CubeCL Kernel
                    └→ CubeK 高性能算子
                         ↓
                  CubeCL runtime → 设备
```

选择 Rust 不是为了假装机器学习系统只有一种语言。Python、C++、CUDA
仍然是理解现有生态和接口边界的重要组成部分。统一的 Rust 主线只是让我们
能在同一套类型、所有权与并发语义下，从模型定义一路追踪到 Kernel 和
运行时，减少因频繁切换技术栈而产生的认知断点。

## 本章问题

机器学习系统如何把模型定义转换为跨设备执行、训练和部署的程序？Burn
各组件在这条路径上分别承担什么职责？一个读者又该如何区分稳定的系统原理、
固定源码中的事实和仍在演进的项目能力？

## 学习目标

完成本章后，你应该能够：

1. 从计算、数据、硬件和运行生命周期四个角度描述机器学习负载；
2. 解释现代机器学习系统需要共同满足的六类设计目标；
3. 画出从用户接口、张量执行、IR、Kernel 到异构设备的分层路径；
4. 区分 Burn、CubeCL、CubeK 与 burn-onnx 的职责；
5. 理解 Burn 0.22 中 `Tensor`、`Device` 和后端分派的基本关系；
6. 使用 `pins.toml` 和第一章实验核对教材所依赖的真实源码快照。

## 先修知识

本章只要求掌握 Rust 的基本语法和常见机器学习术语。尚未接触自动微分、
GPU 编程或分布式系统也没有关系：本章先建立地图，后续章节再逐层进入实现。

## 本章路线

我们先把“应用”转换为可分析的系统负载，再从设计目标得到分层架构；随后
把这套框架无关架构映射到固定版本的 Burn 技术栈，最后通过一个 CPU 实验
验证“源码快照 → Cargo feature → Device → Backend → Tensor 执行”的
最短路径。
